# Proposal

## Why

用户闯关到一半退出后，本局进度仅存在本地 Storage，进程中断或被新开局覆盖后题目与作答会丢失，白白浪费已生成的题目。需要把「未完成闯关」持久化并可继续作答；若题目已全部答完但未进入报告页就返回，也应视为通关并静默生成报告，便于在历史记录中回看。

## What Changes

- 闯关进行中的题目、已作答进度与当前题号持久化到服务端，退出后仍可从「未完成」入口继续闯关。
- 历史闯关列表展示未完成记录（可继续）与已通关记录；点击未完成项恢复本局面板并接着答。
- 首页独立展示未完成闯关：最多 3 条，与历史中的未完成同源同步；超出部分仅在历史页查看；无未完成时展示提示语；每条右侧用进度条展示已闯进度（已答/总题）。
- 在历史页续玩并完成答题后，首页未完成区在再次展示时 MUST 与历史一致（该局不再出现在未完成列表）。
- 全部题目答完但用户未点击「查看报告」就返回：按通关处理，后台静默生成答题报告并结算奖励，历史中可查看报告。
- 新开局不再静默冲掉唯一可恢复的进度：未完成局保留在服务端，本地活跃会话切换时以服务端记录为准可恢复。
- 本地 Storage 仍作答题页缓存，权威状态改为服务端会话。

## Capabilities

### New Capabilities

- `challenge-progress`: 闯关会话进度持久化、未完成恢复、首页未完成预览（≤3 条 + 进度条 + 空态）、答完未看报告时的静默通关与报告生成，以及历史列表中的未完成/已完成状态呈现。

### Modified Capabilities

- （无）既有 `quiz-generation` / `knowledge-*` 规格只管出题与知识库分流，不描述会话生命周期；本变更用新能力覆盖，不改写其出题要求。

## Impact

- 后端：`QuizSession`（或等价会话表）需支持进行中状态与部分作答；新增/扩展 sessions 保存与恢复 API；`complete` / 报告生成可在「答完即走」路径静默触发；`GET /history` 需返回未完成项及可区分状态。
- 前端：`pages/quiz`、`pages/generate`、`pages/report`、`pages/history`、`pages/home` 需读写服务端进度；首页未完成区（最多 3 条、进度条、空态提示）与历史未完成同步；答完离开时触发静默通关。
- 不影响出题合同本身；对历史列表客户端需兼容新的 `status`（已有字段默认为 `completed`）。
