# 知识库刷题优化需求分析文档

> 产品名：**衰衰闯关**（任意知识闯关学习助手）  
> 形态：微信小程序｜市场：中国｜语言：默认中文  
> 背景：私有知识库（RAG）已落地（见 OpenSpec change `add-private-knowledge-bases`）  
> 版本：v0.2（开放问题已锁定）｜日期：2026-11-14  
> OpenSpec change：`openspec/changes/optimize-kb-drill-mode/`  
> 说明：本文整理「RAG 出题覆盖不足」相关讨论结论，并给出**知识库双模式（刷题 / 学透）**的需求范围与规则；**不含详细技术方案实现**（方案设计可另文）。

---

## 1. 文档目标

在现有「上传资料 → 切块 Embedding → Chroma 检索 → Agent 取知 → 模型出题」链路可用的前提下，回答并落地：

1. 为什么题库类 PDF 会出现「来来去去总是那几题、大量题目刷不到」；
2. 「加题量 / 加大 TopK / 上 Rerank」为什么不够；
3. 如何区分 **刷题模式**（覆盖整本习题）与 **学透模式**（吃透学习资料要点）；
4. 模式误选时的检测、建议与降级规则；
5. 本期建议做什么、明确不做什么。

---

## 2. 讨论纪要摘要（从 RAG 优化话题起）

### 2.1 现状问题（已确认）

- 当前知识库开局是 **语义检索 Top-K 片段（默认约 6 块）→ 模型根据片段出题**，不是「从题库里抽题」。
- 开局线索常近似「根据知识库某某出题」，查询语义稳定 → **每次命中块高度重叠**。
- 文档按固定长度切块（约 900 字），百题级题库会散落在大量块中；Top-K 只能覆盖一小部分。
- **无「已出/已刷」记忆，无轮转/随机覆盖策略**；也尚未上独立 Rerank（仅为相似度 Top-K）。
- 因此：对「上传的是 100+ 道题的习题 PDF」场景，体验更像「总在最相关几页里打转」，**无法支撑期末全面刷题**。

### 2.2 两类文档、两种目标（已对齐）

| 文档类型 | 用户目标 | 适合路径 |
|----------|----------|----------|
| 学习资料（讲义/课本/笔记） | 通过做题理解整份材料的**要点与知识结构** | 结构化覆盖 + RAG/要点地图 + 模型出题（学透） |
| 题库类（习题集/真题 PDF） | **尽量刷全/刷广**，减少遗漏 | 拆题入库 + 数据库抽题 + 已刷记录（刷题） |

结论：**不能用同一套「只靠 Top-K RAG 出题」硬扛两种目标。**

### 2.3 为什么「只加题量」不够

- 题量变大、检索上下文仍只有 Top-K → 模型要么重复编题，要么为塞更多原文 **急剧消耗 token**。
- Rerank 只能让 Top-K「更准」，**不能 magically 覆盖整本 100 题**。
- 真正决定覆盖的是：**选题策略（抽哪些题/哪些块）**，不是单次 Prompt 里塞多少字。

### 2.4 刷题模式的产品直觉（已对齐）

- 刷题模式应：**拆题进业务库（MySQL）→ 按题量抽取 → 原题（或结构化题目）给用户刷**。
- 发题主路径 **不依赖**「每局向量检索 + 大模型生成整卷」。
- 模型/向量在刷题路径上变为可选：
  - **入库拆题**（版式乱时一次性辅助识别「哪里是一道题」）；
  - **学透模式**仍用 RAG + 生成；
  - 后续增强（错题讲解、变式改编等）可后置。

### 2.5 已刷记录与上下文（已对齐）

- **已刷记录存 MySQL**（如 user + kb + question_id + 时间），不在模型上下文里堆历史。
- **轮转在后端完成**：查出未刷/久未刷 → 抽出本局 N 道 → **只把这 N 道**交给前端或（必要时）模型。
- 因此：**库可以很大，每局喂给模型/页面的要小**；轮转不会因为「记已刷」而撑爆上下文。
- 向量库哪怕有几千块，学生规模下 ANN 通常不是瓶颈；**瓶颈是把大量原文塞进 LLM**。

### 2.6 模式由谁决定（已对齐）

- 不能只靠用户手动选模式：刷题模式下传讲义，可能拆题失败、拆出乱题、或几乎无选项/答案。
- 推荐策略：**后台检测 + 默认建议 + 用户确认**；危险时自动降级并说明。
  - 不是「静默改模式不告知」；
  - 也不是「只弹提醒仍按错模式硬跑」。

### 2.7 学透模式对切片的要求（已对齐）

- 「吃透整份材料」靠的是 **结构化覆盖**（章节/标题/要点地图 + 轮转），不是一次通读全文进模型，也不是「切得越碎越好」。
- 固定字符切块对讲义不够；更合理的是按标题/章节切，并缓存章节摘要或考点列表，再按章节出题。

## 3. 已确认约束（讨论拍板）

| 项 | 结论 |
|----|------|
| 题库 PDF 主路径 | **拆题 + MySQL 抽题**，不以每局 RAG Top-K 生成作为覆盖手段 |
| 学习资料主路径 | **学透**：要点/章节覆盖 +（仍可用）RAG/生成 |
| 模式挂载级别 | **知识库级**：一整库只能是刷题 **或** 学透，不可混用 |
| 新文档不符模式 | **提醒用户**（见 §6.1 / §8）；不静默改库模式 |
| 题量选项 | 主要服务 **刷题抽题的本局 N**；不能单独当作 RAG 覆盖方案 |
| 已刷记录 | **MySQL**；轮转在应用层，不把历史全量塞进 Prompt |
| 向量库角色 | 学透检索；刷题发题可不依赖；勿为刷题把「每题一条向量」当成唯一方案 |
| 模式选择 | 用户可选，但 **后台检测建议 + 确认**；危险场景阻断/引导，并告知 |
| 刷题题型 | **仅单选 / 多选 / 判断**；按正式题库文档拆题 |
| 图片题 | **不做展示**；拆题时过滤掉，不入库或标记跳过 |
| 文本范围 | 仅文本题；学透模式生成策略可后续再调 |
| 与现网 RAG | 现有私有知识库能力保留；本优化是 **增补双模式与覆盖策略**，不是推倒重来 |

## 4. 需求范围

### 4.1 建议纳入（In Scope）— 分优先级

#### P0（刷题闭环，优先）

| 编号 | 功能 | 说明 |
|------|------|------|
| Q1 | 知识库模式标识 | **库级**「刷题 / 学透」；创建或首次确认后锁定；同库文档须符合该模式 |
| Q2 | 题库拆题入库 | 刷题库文档解析并拆成结构化题目（题干、选项、答案；解析见 Q9） |
| Q3 | 拆题结果校验 | 题数、结构完整度；过低/不像题/不符刷题库 → **提醒用户** |
| Q4 | 模式建议与确认 | 后台建议并预选；用户确认后锁定**整库**模式 |
| Q5 | 本局题量选择 | 刷题开局可选 N（如 6/12/20…，上限与库内可用题数取 min） |
| Q6 | 抽题开局 | 从 MySQL 抽取单选/多选/判断文本题进入闯关流（原题） |
| Q7 | 已刷记录 | 作答后写入已刷；优先未刷 |
| Q8 | 不符/失败时的引导 | 见 §6.1「降级/阻断」定义：提醒、阻断开刷、提供改学透或换文档，不静默改模式 |
| Q9 | 答案解析补全 | 原文有解析则用原文；**无解析时可用 AI 生成讲解并缓存**（见 §6.5） |
| Q10 | 刷完一轮后的响应 | 未刷池为空时进入「复习轮」流程（见 §6.6），不可无提示地继续当新题 |

#### P1（学透增强）

| 编号 | 功能 | 说明 |
|------|------|------|
| S1 | 更合理切分 | 优先按标题/章节等结构切分，固定长度作回退 |
| S2 | 要点/章节地图 | 入库或首次开局前生成并缓存章节/考点摘要，供覆盖式出题 |
| S3 | 学透覆盖轮转 | 记录已用章节/块，降低「每次同一段」概率 |
| S4 | 学透题量 | 题量仍可调，但生成仍基于「本局选中的要点集合」，禁止无脑塞全文 |

#### P2（体验与增强，可后置）

| 编号 | 功能 | 说明 |
|------|------|------|
| E1 | 刷题进度展示 | 已刷/总题数、覆盖率 |
| E2 | 错题优先 | 错题进入重练队列 |
| E3 | 变式改编 | 在原题基础上可选「AI 改编」（额外消耗模型，默认关闭） |
| E4 | 文档存储 OSS | 与刷题逻辑解耦；上传改云端存储时不改变抽题/学透契约 |

### 4.2 明确不做（Out of Scope，本期讨论口径）

- 用「无限加大 TopK / 通读全文进模型」作为题库覆盖方案；
- 把已刷过的成百上千道题整表塞进单次模型上下文；
- 静默改模式且不告知用户；
- 跨用户共享题库、商业题库版权分发（用户私有上传场景除外的合规议题另案）；
- 扫描件 OCR 专项（现有知识库 Non-Goal 延续，除非单独立项）；
- 本期不强制上独立 Rerank 服务（非覆盖问题的银弹）。

## 5. 核心用户故事

### 5.1 刷题：期末刷完整本习题

1. 用户导入习题 PDF，系统检测「更像题库」，建议刷题模式；用户确认。  
2. 后台拆题完成，详情页可见「共 N 题，已就绪」。  
3. 用户选择本局 20 题 → 开始闯关，刷到的是库内原题（或结构化还原题）。  
4. 再次开局优先未刷题目；全部刷过后可提示已刷完或进入复习轮。  

### 5.2 学透：吃透一份讲义

1. 用户导入讲义，系统建议学透；用户确认。  
2. 入库形成章节/要点结构（P1）；开局按未覆盖要点出题。  
3. 多次闯关逐渐覆盖不同章节，而不是反复同一段。  

### 5.3 误选模式

1. 用户选了刷题但上传讲义 → 拆题数过低 → 提示「更像学习资料，建议改学透」。  
2. 用户确认切换后走学透；或取消后保持失败态，不进入劣质刷题。

## 6. 关键规则（需求级）

### 6.1 模式建议与「降级」含义

- 模式挂在 **知识库**：整库要么刷题，要么学透。  
- 输入：解析文本特征、拆题候选数量、是否含「题号/选项/答案」等。  
- 输出：`suggested_mode` ∈ {`drill`, `master`} + 原因文案；预选后 **用户确认生效**。  

本文所说的「降级 / 引导」指下列情况（**不是**后台偷偷改库模式）：

| 场景 | 系统行为 |
|------|----------|
| 新文档上传后，检测结果与**当前库模式**不符（如刷题库来了讲义） | **提醒用户**：文档可能不适合本库；可选删除该文档、换文件，或（需用户明确操作）将整库改为学透 |
| 刷题库拆题失败 / 可用文本题为 0 | **阻断刷题开局** + 说明原因；提供「改学透」或「重新上传」入口 |
| 拆出大量图片题被过滤后所剩无几 | 提示「已过滤图片题，可用文本题过少」；由用户决定是否换文档或改模式 |

默认口径：**先阻断错误路径并提醒，不自动改库模式**；改模式必须用户点确认。

### 6.2 刷题抽题

- 题型仅 **单选 / 多选 / 判断**，且为 **文本题**；图片题过滤。  
- 本局题量 N：用户可选，且 `1 ≤ N ≤ min(用户选择上限, 库内可用题数)`。  
- 默认优先级：未刷 > 久未刷 > 最近已刷（复习轮见 §6.6）。  
- 可用题不足 N：有多少出多少，并提示。  
- 发题 **不要求** 调用 Embedding 检索整库；**不要求** 为凑 N 而把全文送进大模型。

### 6.3 学透出题（相对现状的改进方向）

- 禁止仅依赖「单一固定线索 + 固定 Top-K」作为唯一覆盖手段（P1 起引入章节/块轮转或要点地图）。  
- 单局仍只使用有限上下文窗口；覆盖靠多局累计与选题策略。  
- 学透侧题型/生成策略可后续单独调整，不绑死刷题题型集合。

### 6.4 与现有闯关体验的关系

- 答题页、判分、报告、EXP 等尽量复用。  
- 刷题模式题目来源从「生成本局 JSON」变为「抽题组装本局 JSON」（字段对齐现有题型结构）。  
- 学透模式可继续走生成链路，但取知策略按本需求升级。

### 6.5 答案与解析

- 原文能拆出答案 → 用原文答案判分。  
- 原文有解析 → 展示原文解析。  
- 原文**无解析** → **允许 AI 生成解析**，提升讲解体验；生成结果应 **缓存到该题**，避免每次作答重复耗 token。  
- 建议触发时机：用户提交该题后按需生成（懒生成），而非入库时对百题全部预生成（控制成本）。  
- 展示上需可区分「来自原文档」与「AI 生成」（文案角标即可）。

### 6.6 全部题目轮转完毕（刷题）

当知识库刷题模式下 **未刷池为空**（用户已轮转完当前库全部可用文本题）时：

1. 开局前明确提示：「本库题目已全部刷过一遍」。  
2. 提供可选动作（至少包含）：  
   - **开始复习轮**：从已刷题中再抽 N 道（可优先错题，若已做 E2；否则随机/久远优先）；  
   - **重置刷题进度**：清空已刷记录，重新从第一轮未刷池开始（需二次确认）；  
   - **取消**：返回详情。  
3. **禁止**在无提示情况下假装还有「新题」继续抽。  

### 6.7 拆题方式（规则 vs 小模型）说明

- **纯规则解析**：成本低、速度快、可预期；对版式规范的正式题库往往够用；对乱版式/双栏/答案分离 PDF，**召回与正确率通常更低**。  
- **小模型辅助拆题**：成本更高；乱版式下正确率通常更好。  
- 推荐实现策略（需求允许）：**规则优先，失败或置信度低再小模型补拆**（混合），而不是二选一绝对化。

## 7. 验收要点（草稿）

| 编号 | 验收项 |
|------|--------|
| A1 | 题库 PDF 在刷题模式下可拆出题目列表，数量级与文档题量大致同量级（允许解析损耗，需有阈值与失败提示） |
| A2 | 连续多次「同库刷题开局」在未刷完前，题目重复率显著低于当前纯 RAG（需约定简单统计方式，如连续 3 局未刷池碰撞率） |
| A3 | 已刷记录写入后，下一局优先未刷题 |
| A4 | 选择题量只影响本局 N，不会触发「整本 PDF 进模型」 |
| A5 | 刷题模式误传讲义时，用户能看到建议/失败说明，且不会在无可用题时静默开刷空卷或乱题 |
| A6 | 学透路径下现有知识库上传与向量入库仍可用；P0 不强制完成章节地图亦可先保留现状 RAG（需在排期中标明） |

## 8. 开放问题结论（2026-11-14 确认）

| # | 问题 | 结论 |
|---|------|------|
| 1 | 模式挂载级别 | **知识库级**；整库刷题或整库学透。新文档不符 → **提醒用户**，不静默改模式 |
| 2 | 规则拆题 vs 小模型 | 规则成本低、乱版式正确率通常更低；小模型相反。采用 **规则优先 + 低置信度再模型补拆** |
| 3 | 无解析时 | **允许 AI 生成解析并缓存**；懒生成（作答后），角标区分来源；有原文解析优先原文 |
| 4 | 「降级」指什么 | 指不符模式/拆题失败时的 **提醒 + 阻断错误开刷 + 提供改学透/换文档**；默认不自动改库模式 |
| 5 | 题型 | 刷题仅 **单选 / 多选 / 判断**；学透生成后续可再调 |
| 6 | 图片题 | **过滤**，不做展示；仅文本题 |
| 7 | 全部轮转完 | 提示已刷完一遍 → **复习轮 / 重置进度 / 取消**；禁止无提示当新题继续抽 |

仍可在实现期细化、但不挡 P0 立项的项：规则/模型拆题的置信度阈值具体数字；复习轮是否默认「错题优先」。

---

## 9. 建议落地顺序

1. **P0 刷题**：库级模式 + 拆题表 + 抽题 + 已刷 + 题量 + 不符提醒/阻断 + 刷完复习轮；解析懒生成可同迭代或紧随；  
2. **P1 学透**：结构切分 + 要点地图 + 覆盖轮转；  
3. **P2**：进度展示、错题本、可选 AI 变式、OSS 存储迁移。
