# 学透要点地图 — 验收指南

## 0. 你之前为什么「看起来没变」

实现时只改了 `frontend/src`，并用 `tsc` 做了类型检查，**没有**跑 `npm run build:weapp`。  
微信开发者工具读的是 `frontend/dist`。若 dist 时间戳仍是改代码之前，界面就会还是旧版。

**正确看前端的步骤：**

1. 在 `frontend` 目录执行：`npm run build:weapp`（或开发时用 `npm run dev:weapp` 热更新）
2. 打开微信开发者工具 → 项目目录指向 `frontend/dist`（或你们平时用的目录）
3. 点「编译」；必要时清缓存后再编译
4. 进入**学透模式**知识库详情，应能看到「要点已覆盖 a / 共 b」或「要点地图生成中…」

## 1. 表与字段中文含义（速查）

| 表/字段 | 含义 |
|---------|------|
| **knowledge_bases.master_map_status** | 要点地图状态：`pending` 生成中 / `ready` 就绪 / `failed` 失败 |
| **knowledge_bases.master_map_error** | 地图失败原因文案 |
| **knowledge_bases.master_point_count** | 要点总数（冗余，方便详情展示） |
| **kb_master_sections** | 学透「章节/节」 |
| └ title / ordinal / summary | 标题、顺序、短摘要 |
| └ document_id | 来自哪份文档 |
| **kb_master_points** | 学透「要点/考点」（出题主依据） |
| └ title / summary | 短标题、1–3 句说明 |
| └ is_active | 1=有效；替换文档后旧点会清掉 |
| **kb_master_point_coverage** | 用户对要点的覆盖进度（类似刷题的练习表） |
| └ seen_count / last_seen_at | 见过几次、最近一次时间 |

用 Navicat / DBeaver 看表时，跑完带 COMMENT 的迁移后，备注列应显示中文。

## 3. 手工验收清单（小程序 + 后端都要开着）

### A. 地图生成

1. 新建知识库 → 确认模式为**学透** → 上传一份带标题的 MD/PDF  
2. 文档变为「就绪」后，详情应出现：  
   - 先可能是「要点地图生成中…」  
   - 稍后变为「要点已覆盖 0 / 共 N」  
3. 库表：`master_map_status='ready'`，`kb_master_points` 有行

### B. 开局覆盖

1. 地图 ready 后点「开始闯关」做一局（可中途退出）  
2. 详情「已覆盖」应变大；`kb_master_point_coverage` 出现对应 `user_id` + `point_id`  
3. 再开一局，选中的要点应更偏向**尚未覆盖**的点（多局后覆盖率上升）

### C. 全覆盖复习轮

1. 把该库要点都开局覆盖完（或手动把 coverage 记满）  
2. 再点开始 → 应弹出「本库要点已过一轮」：复习 / 重置覆盖 / 取消  
3. 重置后「已覆盖」回到 0，地图本身还在

### D. 地图未就绪降级

1. 找一个 `master_map_status` 为 pending/failed 的库（或点「重建要点地图」后立刻开局）  
2. 应提示可先用旧检索开局（非覆盖学透）  
3. 文档状态仍应是「就绪」（地图失败不把文档打回失败）

### E. 替换文档清进度

1. 学透库已有覆盖进度时，再上传新文档（替换）  
2. 旧 `kb_master_points` / coverage 应清空；进度归零  
3. 新文档入库后重新生成地图

### F. 改刷题清地图

1. 学透库改为刷题并确认  
2. 要点表与覆盖应清除；详情不再走学透进度文案

## 4. 接口冒烟（可用浏览器或 curl，需登录 token）

| 方法 | 路径 | 期望 |
|------|------|------|
| GET | `/api/v1/knowledge-bases/{id}/master-status` | 返回 map_status、total/covered/uncovered |
| POST | `/api/v1/knowledge-bases/{id}/master-map/rebuild` | status 变 pending，随后变 ready/failed |
| POST | `/api/v1/knowledge-bases/{id}/reset-master-coverage` | `{ok:true}`，覆盖清零 |

非本人库 → 404。

## 5. 验收通过标准（产品口径）

| 标准 | 怎么算过 |
|------|----------|
| 可解释覆盖 | 详情可见「已覆盖 / 共要点」 |
| 多局不重复踩同一片 | 连续两局主要点重叠明显低于「每次同一批」 |
| 单局上下文可控 | 开局不靠塞全文；走要点路径 |
| 换文档干净 | 替换后旧点与覆盖消失，进度归零 |
