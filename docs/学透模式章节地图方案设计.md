# 学透模式章节地图方案设计

> 产品名：**衰衰闯关**  
> 形态：微信小程序｜市场：中国｜语言：默认中文  
> 背景：知识库双模式（刷题 / 学透）已落地；学透仍走「固定字符切块 + Top‑K 语义检索 + 模型出题」  
> 版本：v0.1｜日期：2026-11-15  
> 关联：[`docs/知识库刷题优化需求分析文档.md`](./知识库刷题优化需求分析文档.md) P1（S1–S4）；OpenSpec change 建议名 `enhance-master-chapter-map`（待开）  
> 说明：本文为**实现前方案设计**，不含编码；拍板后可再开 OpenSpec change 拆任务。

## 1. 文档目标

回答并锁定：

1. 为何当前学透无法「靠做题摸清整份材料」；
2. 章节/要点地图缓存在哪里、何时生成、如何失效；
3. 开局如何按「未覆盖要点」取知并出题；
4. 与现有单文档库、刷题模式、Chroma RAG 的边界。

**成功标准（验收口径）：**

| 标准 | 含义 |
|------|------|
| 可解释覆盖 | 详情页可见「本章节要点数 / 已覆盖要点数」 |
| 多局不重复踩同一片 | 连续两局开局，选中的主要点集合重叠率显著低于现状「固定线索 + Top‑6」 |
| 单局上下文仍可控 | 禁止把全文塞进一次 Prompt；本局只带选中要点 + 少量补充片段 |
| 换文档干净 | 一库一份文档替换后，旧要点地图与覆盖记录一并清掉 |

## 2. 现状与问题

### 2.1 现状参数（代码实值）

| 项 | 现状 |
|----|------|
| 切块 | `RecursiveCharacterTextSplitter`，约 **900 字 / overlap 120** |
| Top‑K | **`k=6`** |
| 相似度阈值 | **无**（只排序取前 K） |
| 覆盖记忆 | **无** |
| 开局线索 | 近似「根据知识库某某出题」，语义稳定 → 易重复命中 |

### 2.2 问题本质

学透的目标是**结构化覆盖材料要点**，不是「每次找最像查询的 6 段再编题」。  
固定线索 + Top‑K 只能服务「局部巩固」，不能服务「多局吃透整篇」。

---

## 3. Goals / Non-Goals

### Goals

- **S1** 结构优先切分（标题/章节），字符切分为回退。
- **S2** 生成并**持久化**章节/要点地图（摘要 + 考点列表）。
- **S3** 按用户维度记录已覆盖要点，开局优先未覆盖。
- **S4** 本局题量仍可选，但生成依据是「本局选中的要点集合」，禁止无脑塞全文。
- 复用现有：异步出题任务、闯关页、报告/EXP；学透仍可调用 Chroma 作**补充检索**。

### Non-Goals（本期不做）

- 独立 Rerank 服务、OCR、多文档合订本（产品已定**一库一份文档**）。
- 把要点地图只存在小程序 Storage 或只塞进 Chroma metadata。
- 刷题模式改造（继续走 `kb_questions` 抽题）。
- 「一次通读全文进模型」当覆盖方案。

## 4. 核心决策

### 4.1 缓存放哪里

| 数据 | 存储 | 理由 |
|------|------|------|
| 章节节点、要点、摘要、顺序 | **MySQL** | 要精确列表、轮转、进度展示；与刷题 `kb_questions` 同级 |
| 原文向量块 | **Chroma**（沿用 `kb_{id}`） | 语义补检索；不当事要点主库 |
| 本局临时状态 | 小程序 Storage | 仅当前闯关 |

**否决**：要点只进 Chroma → 无法可靠做「未覆盖优先」。  
**否决**：要点只进前端 → 换机丢失、无法服务端选题。

### 4.2 与单文档产品规则对齐

- 每库最多 **1** 份文档；再传 = 替换。
- 替换时：**删旧文档 + 清 Chroma 块 + 清要点地图 + 清覆盖记录**，再重建。
- 改模式为刷题：停用/清空学透地图（或整库按刷题管道重建，与现 `confirm-mode` 一致）。

### 4.3 生成时机

1. **主路径**：学透文档入库向量成功后，异步生成要点地图（与 ingest 同背景任务链，或紧随其后的第二任务）。
2. **回退**：地图未就绪时，开局可短暂走现状 Top‑K（并提示「要点地图生成中」）；地图 ready 后强制走覆盖开局。
3. **失败**：地图生成失败 → 文档仍可 `ready`（向量可用），但详情展示警告；开局降级为旧 RAG，并允许「重试生成地图」。

### 4.4 相似度与 Top‑K（学透新开局）

| 项 | 新方案 |
|----|--------|
| 主选题 | **不依赖**「整库 Top‑K 当唯一来源」；先从 MySQL 选未覆盖要点 |
| 补检索 | 可用选中要点文案作 query，Chroma **`k=3~4`** 取原文片段贴到 Prompt（可选） |
| 阈值 | 本期仍可不设硬阈值；若噪声大，再加「最低分数」或「仅同 chapter 块」过滤（后置） |

## 5. 数据模型（MySQL）

### 5.1 `kb_master_sections`（章节/节）

| 字段 | 说明 |
|------|------|
| `id` | PK |
| `knowledge_base_id` | FK |
| `document_id` | FK |
| `ordinal` | 顺序 |
| `title` | 章节标题（无标题可用「第 n 段」） |
| `summary` | 短摘要（可空，模型填） |
| `source_span` | 可选：原文起止偏移或页码提示 |
| `created_at` / `updated_at` | |

### 5.2 `kb_master_points`（要点/考点）

| 字段 | 说明 |
|------|------|
| `id` | PK |
| `section_id` | FK |
| `knowledge_base_id` | FK（冗余便于按库查询） |
| `ordinal` | 节内顺序 |
| `title` | 考点短标题 |
| `summary` | 1–3 句要点说明（出题主依据） |
| `keywords_json` | 可选关键词 |
| `is_active` | 文档替换后旧点置 0 或物理删 |
| `created_at` / `updated_at` | |

### 5.3 `kb_master_point_coverage`（用户覆盖）

| 字段 | 说明 |
|------|------|
| `id` | PK |
| `user_id` | FK |
| `knowledge_base_id` | FK |
| `point_id` | FK |
| `seen_count` | 进入过含该点的局次数 |
| `last_seen_at` | |
| 唯一键 | `(user_id, point_id)` |

> 与刷题 `kb_question_practice` 对称：刷题记题，学透记要点。

### 5.4 文档/库状态扩展（可选字段）

在 `knowledge_documents` 或 `knowledge_bases` 增加：

- `master_map_status`：`pending` / `ready` / `failed`
- `master_map_error`：失败原因
- `master_point_count`：冗余计数，详情展示用

## 6. 处理流水线

```text
上传/替换（单文档）
  → 文本提取
  → 结构切分（标题优先，否则字符切分回退）
  → Embedding 写入 Chroma（保留，供补检索）
  → 异步：规则/模型生成 sections + points → 写入 MySQL
  → master_map_status = ready

开局（mode=master）
  → 断言地图 ready（或降级旧 RAG）
  → 按题量 N 估算需要的要点数 M（如 M = min(总要点, max(2, ceil(N/2)))）
  → 取样：未覆盖优先；若全覆盖 → 提示复习轮（随机/久远优先）
  → 组装 Prompt：选中要点摘要 +（可选）Chroma 补片段
  → 现有 structured 出题 → 闯关
  → 局开始或局结束：写入/更新 coverage
```

### 6.1 结构切分策略

1. Markdown / 带 `第 x 章`、`##` 标题的文本：按标题切 section。  
2. 纯散文：按大段落聚合，每 section 目标长度约 800–1500 字。  
3. 每个 section 内由模型抽 **2–8** 个要点（限总要点上限，如每库 ≤ 80，防止爆表）。

### 6.2 开局取样

- 优先 `coverage` 不存在或 `seen_count=0`。  
- 不足则取 `last_seen_at` 最久。  
- 全覆盖：前端 ConfirmModal「本库要点已过一轮」→ 复习 / 重置覆盖 / 取消（对齐刷题复习轮体验）。

### 6.3 Prompt 约束（相对现状）

- 输入改为「本局要点列表 + 可选原文摘录」，而非「单一库线索 + 任意 Top‑6」。  
- 明确：题目必须覆盖所列要点中的多数；禁止字面弱题（沿用现规则）。

## 7. API 增量（草图）

| 方法 | 路径 | 作用 |
|------|------|------|
| GET | `/knowledge-bases/{id}/master-status` | 地图状态、section/point 计数、未覆盖数、是否需复习提示 |
| POST | `/knowledge-bases/{id}/master-map/rebuild` | 手动重跑地图（失败重试） |
| POST | `/knowledge-bases/{id}/reset-master-coverage` | 清空该用户在本库的要点覆盖 |
| POST | `/quiz/tasks` | 学透路径内改为「要点取样 + 生成」（对前端可仍透明） |

错误码建议：`MASTER_MAP_PENDING`、`MASTER_MAP_FAILED`、`MASTER_EMPTY`（无要点）。

## 10. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 无标题讲义切章不准 | 段落聚合 + 模型归并；允许用户「重建地图」 |
| 要点生成贵/慢 | 限要点上限；异步；失败可降级旧 RAG |
| 覆盖记在开局还是交卷 | **推荐开局即记 seen**（防弃局刷同一点）；可选交卷再加 correct 权重（P2） |
| 与旧 Top‑K 行为不一致 | 详情标明「覆盖学透」；地图未就绪明确降级文案 |

---

## 11. 迁移与回滚

1. Alembic：三张新表 + 可选 `master_map_status` 列。  
2. 已有学透库：首次进入详情或下次 ingest 触发 rebuild；未 rebuild 前保持旧开局。  
3. 回滚：开局忽略地图，恢复 `k=6` 强制检索路径。

## 12. 建议落地顺序

1. 表结构 + 替换文档时级联清理  
2. 结构切分 + 异步生成地图  
3. `master-status` + 详情进度 UI  
4. 开局取样改 `gather_research` / quiz 学透分支  
5. 复习轮 + 重置覆盖  
6. 补检索调参与手工验收长讲义

## 13. 已锁定假设（来自讨论）

- 一库一份文档，再传即替换。  
- 要点地图主缓存 = **MySQL**；Chroma 不当事主库。  
- 本期不靠加大 Top‑K / 上 Rerank 解决覆盖。  
- 学透与刷题进度表分离，不混用 `kb_question_practice`。

## 14. 仍可在实现期微调（不挡开干）

- 本局要点数 M 与题量 N 的具体公式。  
- 覆盖记在开局还是通关（默认开局）。  
- 补检索 `k` 取 3 还是 4。  
- 是否在详情展示章节列表（只读）。
